# Release Artifact Bundle Layout

Date: 2026-05-13

This document defines the recommended layout for optional public saved-array
audit assets. It is the bridge between the private research workbench and the
public v1 reproduction repo when maintainers choose to publish paper-used
intermediate arrays.

The goal is simple: an external reader should be able to unpack an optional
audit bundle, point `ARTIFACT_ROOT` at it, and run the public validators,
tables, and figures without knowing any private cluster paths. This audit path
is separate from the default full paper-style rerun path, where users regenerate
features, SAE codes, probes, and analysis artifacts themselves.

## Bundle Root

Use one artifact root per release bundle:

```text
feature_economy_artifacts_v1/
  run_plan/
  manifests/
  features/
  codes/
  probes/
  analysis/
  index/
  tables/
  figures/
  README.md
```

The bundle may omit `figures/` if only CSV tables are released. It may omit
`features/` or `codes/` only if the release is explicitly an analysis-only
bundle and includes the downstream artifacts needed by the paper tables.

## Required Top-Level Metadata

Recommended files:

- `README.md`: short description, release date, source paper/version, and known
  limitations.
- `run_plan/reproduction_run_plan.json`: run matrix generated by
  `feature-economy plan-runs` or a documented subset plan.
- `run_plan/reproduction_run_plan.csv`: human-readable copy of the run matrix.
- `run_plan/artifact_bundle_check_final.json`: final output of
  `feature-economy check-bundle --require-complete`.
- `index/artifact_index.json`: generated with `index-artifacts --require-valid`.
- `index/artifact_index.csv`: human-readable artifact index.

## Directory Conventions

Use stable identifiers from `configs/`:

```text
features/{model_id}/{task_id}/l{layer}/
codes/{sae_id}/{task_id}/val/
probes/native/{model_id}/{task_id}/val/
probes/sae/{sae_id}/{task_id}/val/
analysis/availability/{sae_id}/{dataset_id}_{split}/
analysis/ranking/{sae_id}/{task_id}/val/
analysis/contribution/{sae_id}/{task_id}/val/
analysis/subset_usage/{sae_id}/{task_id}/val/
analysis/ablation/{sae_id}/{task_id}/val/
```

For layer sweeps, include the layer in `sae_id` and use one directory per SAE.
For alternative rankings, add a suffix that preserves the original ranking:

```text
analysis/ranking_hybrid/{sae_id}/{task_id}/val/
analysis/ranking_validation_contribution/{sae_id}/{task_id}/val/
```

## Required Files By Stage

These are the files checked by `feature-economy check-bundle`.

| Stage | Required files |
| --- | --- |
| `feature_extraction` | `features.npz`, `feature_extraction_summary.json`, `run_manifest.json` |
| `sae_code_extraction` | `codes.npz`, `sae_code_summary.json`, `run_manifest.json` |
| `native_probe` | `native_probe_summary.json`, `probe_logits.npz`, `run_manifest.json` |
| `sae_probe` | `sae_probe_summary.json`, `probe_logits.npz`, `run_manifest.json` |
| `availability` | `availability_summary.json`, `run_manifest.json` |
| `feature_ranking` | `task_feature_ranking.json`, `run_manifest.json` |
| `contribution_scores` | `contribution_scores.npz`, `contribution_scores_summary.json`, `run_manifest.json` |
| `subset_usage` | `subset_usage_summary.json`, `run_manifest.json` |
| `feature_ablation` | `feature_ablation_summary.json`, `run_manifest.json` |

Optional but recommended validation reports:

- `array_validation.json` next to each `features.npz`, `codes.npz`,
  `probe_logits.npz`, `targets.npz`, or `contribution_scores.npz`.
- `index/artifact_metadata_sanitization_report.json` from
  `scripts/package_artifact_bundle.sh`, proving the packaged metadata was
  scanned for private absolute path markers.

## Manifests And Targets

If the release includes manifests, place them under:

```text
manifests/imagenet/{train,val}_manifest.jsonl
manifests/nyuv2/{train,val}_manifest.jsonl
manifests/ade20k/{train,val}_manifest.jsonl
manifests/clevr_count/{train,val}_manifest.jsonl
```

Dense target arrays should be colocated with their task manifests or clearly
referenced from the bundle README:

```text
manifests/nyuv2/val_targets.npz
manifests/ade20k/val_targets.npz
```

Do not include restricted raw images unless licensing permits redistribution.
Saved features, codes, probe logits, and summaries are the preferred public
release assets.

## Validation Commands

From `public_repro/`:

```bash
export ARTIFACT_ROOT=/path/to/feature_economy_artifacts_v1
export PYTHONPATH=$PWD/src

python -m feature_economy.cli.main check-bundle \
  --run-plan-json "$ARTIFACT_ROOT/run_plan/reproduction_run_plan.json" \
  --artifact-root "$ARTIFACT_ROOT" \
  --output-json "$ARTIFACT_ROOT/run_plan/artifact_bundle_check_final.json" \
  --require-complete

python -m feature_economy.cli.main index-artifacts \
  --input-dir "$ARTIFACT_ROOT" \
  --output-json "$ARTIFACT_ROOT/index/artifact_index.json" \
  --output-csv "$ARTIFACT_ROOT/index/artifact_index.csv" \
  --require-valid

python -m feature_economy.cli.main make-tables \
  --artifact-index "$ARTIFACT_ROOT/index/artifact_index.json" \
  --output-dir "$ARTIFACT_ROOT/tables"

python -m feature_economy.cli.main make-figures \
  --table-dir "$ARTIFACT_ROOT/tables" \
  --output-dir "$ARTIFACT_ROOT/figures" \
  --formats png,pdf
```

If `make-figures` is not needed, install without the `figures` extra and skip
the final command.

## Publishing Checklist

Before uploading release assets:

- Run `check-bundle --require-complete`.
- Run `index-artifacts --require-valid`.
- Confirm `run_manifest.json` files contain a non-empty git commit or an
  intentional `FEATURE_ECONOMY_GIT_COMMIT` override.
- Confirm no path in JSON artifacts points to `/Users/`, `/mnt/workspace`, or
  another private machine-specific root unless it is explicitly documented as a
  non-portable provenance field.
- Confirm dataset, checkpoint, and license limitations are stated in the bundle
  `README.md`.
- Confirm table CSVs can be regenerated from the artifact index.

The recommended packaging command is:

```bash
python scripts/create_artifact_bundle_readme.py \
  --run-plan-json "$ARTIFACT_ROOT/run_plan/reproduction_run_plan.json" \
  --output-readme "$ARTIFACT_ROOT/README.md" \
  --bundle-name feature_economy_artifacts_v1 \
  --public-repo-commit "$(git rev-parse --short HEAD)"

bash scripts/package_artifact_bundle.sh \
  --artifact-root "$ARTIFACT_ROOT" \
  --run-plan-json "$ARTIFACT_ROOT/run_plan/reproduction_run_plan.json" \
  --sanitize-replace "/mnt/workspace-20260313/users/YOUR_USER/ijepa_sae_research/artifacts/=${ARTIFACT_ROOT}/" \
  --sanitize-replace "/mnt/workspace/users/YOUR_USER/datasets/=${DATA_ROOT}/" \
  --output-dir /tmp/feature_economy_release_assets \
  --bundle-name feature_economy_artifacts_v1 \
  --force
```

This command reruns `check-bundle --require-complete`, rebuilds the artifact
index and CSV tables, rewrites/scans text metadata for private path markers,
then emits:

```text
feature_economy_artifacts_v1.tar.gz
feature_economy_artifacts_v1.tar.gz.sha256
feature_economy_artifacts_v1_release_manifest.json
```

Use `--with-figures` if the release should also include generated overview
figures. If your bundle already contains no private absolute paths, omit
`--sanitize-replace`; the packaging script still runs a scan-only gate and
fails if private markers remain.

## Tiny Example

For a complete local example of this contract:

```bash
OUTPUT_ROOT=/tmp/feature_economy_tiny_bundle bash scripts/build_tiny_artifact_bundle.sh
python scripts/create_artifact_bundle_readme.py \
  --run-plan-json /tmp/feature_economy_tiny_bundle/run_plan/tiny_dino_imagenet_run_plan.json \
  --output-readme /tmp/feature_economy_tiny_bundle/README.md \
  --bundle-name feature_economy_tiny_bundle \
  --public-repo-commit "$(git rev-parse --short HEAD)"
bash scripts/package_artifact_bundle.sh \
  --artifact-root /tmp/feature_economy_tiny_bundle \
  --run-plan-json /tmp/feature_economy_tiny_bundle/run_plan/tiny_dino_imagenet_run_plan.json \
  --output-dir /tmp/feature_economy_release_assets \
  --bundle-name feature_economy_tiny_bundle \
  --force
```

The tiny bundle is not a scientific result. It exists to demonstrate the exact
file layout, completeness check, artifact index, and table export flow expected
from a real saved-array release bundle.
